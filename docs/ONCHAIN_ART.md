# Frozen onchain editions

The preserved genesis uses `intent-distortions-onchain-v1` in `art-v1.id-operator.testnet`. Future weekly NFTs use `intent-distortions-weekly-onchain-v1` in the fresh financial collection. Both use the **same IDART1 geometry serializer**. There is no compact IDGEN1/global-code dependency in this build.

The weekly worker validates the source provenance, derives the scene from successful swaps and the accepted NEAR AI direction, and persists one bundle before uploading. An IDART1 recipe contains bounded geometry, styling and data-driven motion. Source snapshots stay in a private content-addressed archive; the complete raw transaction dataset is not stored onchain. Public onchain provenance carries its commitment, seed, Merkle root, direction, model, frozen traits and media hashes.

Publication is append-only: `begin_onchain_art` binds release, metadata and commitments; `append_onchain_recipe` accepts exact-offset chunks up to 16 KiB; two `verify_onchain_view` calls independently serialize/hash the still and animation; `mint_onchain_art` requires both verifications and binds the economic token. Verification happens outside the final mint transaction to keep rendering gas separate. A sealed recipe cannot be appended, replaced or minted again. There is no delete, reroll or upgrade method. Fresh deployment creates keyless contract accounts atomically. Do not upgrade old contract state into this different storage layout.

`get_static_svg`, `get_animated_svg` and `get_recipe_chunk` recover the artwork directly from NEAR. `nft_token` embeds the static SVG as a data URI for individual-token metadata. `nft_token_compact` and enumeration use a compact `near://` media identifier to keep financial callbacks small; the site resolves that identifier through hash-checked chain reads. Standard metadata's inline reference contains public provenance. The server pins contract code, checks keylessness and reads each response at a finalized block, with no image-host fallback.

The freeze guarantees the same SVG bytes and recipe, not identical pixels across browser rasterizers. Animation changes presentation over time using frozen controls; it never consumes new swaps or alters the NFT. Six families, palette, material and motion remain shaped by the captured week's activity.

Storage cost varies with recipe size. Each byte is charged by NEAR's storage policy; the dedicated edition account also stores its vault contract. The current format prioritizes exact retention of the tested vector design over the abandoned compact/global-wallet optimization. `prototype.py plan` reports fresh contract setup deposits separately from per-edition costs.
