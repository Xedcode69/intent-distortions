# Architecture

The production application consists of Next.js, private FastAPI, one durable background worker, managed PostgreSQL, content-addressed S3/CloudFront storage, an isolated Node transaction signer, and two Rust contracts. The educational demo is a separate static application with synthetic assets and no integration credentials. [Managed-cloud operations](managed-cloud.md) defines deployment and trust boundaries.

PostgreSQL stores normalized public swap features, frozen epochs and ordered membership, artworks, jobs, weekly releases, complete collection observations, an immutable protocol configuration, signed chain effects, and verified receipt events. Deposit addresses and memos are hashed into pseudonymous record identities before persistence. Beacon, creative response, scene and artifact commitments live in immutable provenance.

The worker commits its policy before observing releases. At the fixed beacon schedule it verifies BLS randomness and the historical block/predecessor, then records complete scans. Only the latest two consistent observations completed before the fixed freeze can seal. A missing/inconsistent/late capture delays the edition. Between release windows a reconciled feature index supports informational progress; frozen membership always comes from a complete cutoff observation.

`epoch_manager.run_epoch` freezes exact inputs before creative generation. Production requires authenticated source classification, correct checkpoint lineage, and the committed policy. The first persisted valid direction is reused, retries are bounded, and only one artwork can exist per epoch/image hash. Renderer-v2 caps scene complexity, aggregates routes and emits a compact Merkle tree index instead of rebuilding every proof. Previously frozen renderer-v1 scenes/files remain unchanged.

Artifact storage uses SHA-256 keys, conditional writes, server checksums and read-back validation. The managed template adds versioning, Object Lock, no-delete worker/API permissions and CloudFront OAC. Provenance references each artifact by hash and itself has an external content hash, avoiding a self-reference. Public CDN bytes are verified before minting. Availability and retention still depend on commissioned infrastructure and operations.

The production worker holds a PostgreSQL session-level advisory lock, probes ownership and stops on loss. Exact signed transactions are journaled before broadcast. Ambiguous outcomes block new nonce reservation until reconciled, so retries do not create fresh transfers merely because a response was lost. The dedicated signer enforces account/contract/method/gas/deposit bounds; the worker account cannot be a treasury beneficiary.

NFT `new_production` binds auction custody and persists an immutable confirmed delivery record when the auction transfers the token. The auction checks custody, enforces bids/deadlines, credits pull-based balances after successful delivery, and supports idempotent callback-loss reconciliation. The delivery record remains valid after the winner resells/transfers the NFT. Deadline-keyed curation history preserves a locked style even after later settlements.

Onchain views remain authoritative. The index ingests successful finalized receipts from configured contracts; it does not provide complete network-wide bid history. Missing receipt history is labeled partial. Merkle membership does not prove provider completeness, private-shard contents or the provider's exact historical internal status. These limits are included in provenance and deployment guidance.

Migrations run with `uv run --locked python -m alembic -c backend/alembic.ini upgrade head`; production startup does not create tables. The root uv workspace provides one Python 3.12 `.venv` and locked graph. Node/npm and Rust/Cargo dependencies have separate locks. CI includes PostgreSQL migrations/lease tests, application/signer/demo checks, contract tests/WASM and container builds; live acceptance remains separate.
